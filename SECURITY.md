# Security Policy

## Supported versions

Pipesor is under active development and has not declared a public supported release. Security fixes are evaluated for the currently maintained codebases on a case-by-case basis.

## Reporting a vulnerability

**Do not disclose vulnerabilities, credentials, access tokens, or exploit details in public issues or pull requests.**

For repositories where **GitHub Private Vulnerability Reporting** is enabled, use the repository's **Security → Report a vulnerability** entry point.

If private vulnerability reporting is not enabled for a repository, report privately by email to any project owner:

- Jhon Galvez — u202323270@upc.edu.pe
- Ramiro Guzman — u202217062@upc.edu.pe

Do not open a public issue, discussion, or pull request for a security report.

Please include the affected repository, relevant version or commit, reproduction steps, potential impact, and suggested mitigation if available. Avoid sharing real secrets or personal data.

## Handling reports

Maintainers will assess incoming reports, coordinate remediation, and decide whether public disclosure or an advisory is appropriate. No fixed response-time or disclosure SLA is promised at this stage.
